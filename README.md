1. 프로젝트 구조 설명
레이어드 계층 구조 : 전체 시스템을 역할에 따라 서로 다른 계층 레이어으로 쪼개서 쌓아 올린 구조입니다.
Controller : 사용자의 요청을 먼저 받고, 결과를 반환하는 곳입니다
(화면 UI나 API엔드포인트가 해당)
Service : 프로그램의 핵심 기능과 규칙이 실행되는 곳입니다.
(실제 업무 로직이 살고 있는 곳)
Repository : 데이터베이스에 접근해서 데이터를 넣거나 가져오는 일만 담당합니다.
Entity / DTO : 실제 데이터가 저장되는 물리적인 공간(MySQL, Oracle등)입니다.
2. 어노테이션 설명
@RestController : 해당 클래스가 프젠테이션 계층의 컨트롤러임을 명시 합니다. 자바 객체를 반환할때 스프링 내부의 message converter를 통해 json형식의 텍스틀 자동 직렬화하여 http 응답 본문에 담아 보냅니다.
@Service : 시스템의 핵심 비즈니스 로직과 도메인 규칙을 수행하는 심장부 역할을 합니다.
@Repository:데이터베이스에 직접 접근하여 데이터의 등록, 조회, 수정, 삭제 작업을 전담하는 계층입니다.
@Entity : 데이터베이스의 테이블과 1:1로 매핑되는 객체로, 데이터의 영속성을 관리합니다.
@GetMapping: 특정 URL로 들어오는 http method요청을 특정 자바 메서드와 연결해 준다.데이터를 조회할때 브라우저 주소창에 치고 들어오는 요청을 처리합니다.
@PostMapping : 데이터를 등록/저장할 때, 보이지 않는 http body에 데이터를 숨겨서 들어오는 요청 처리합니다.
@RequestBody: 클라이언트가 http body에 담아 보낸 json문자열을 자바 객체로 자동 변환해서 메서드의 파라미터에 넣어줍니다.
@Transactional :메서드 실행 전후에 트랙션 시작과 커밋/ 롤백 메커니즘을 자동으로 적용합니다.
@Data : lombok 라이브러리에서 제공하는 기능으로, 컴파일 시점에 생성자 등을 자동으로 생성해 주어 보일러 플레이트 코드를 줄여 주입해줍니다.
